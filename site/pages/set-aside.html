Set a task aside

p on a task, then for how long:

KeyUntil
tTomorrow.
wIn a week.
1-9In that many days.
mSomething happens on it: a comment, a push, a status change.

The task leaves the panes, the counts and the notifications. It is still true; it comes back by itself. The top bar says how many tasks are aside.

See them, bring one back

A pane filtered on is:snoozed lists what is aside. p on a task there brings it back.

aki list --filter is:snoozed

What you set aside is kept in ~/.local/state/aki/snoozed.json.

Notifications

While the board is open, a task that starts asking something of you is announced: a desktop notification says what, once per refresh. A task that comes back from being set aside is not announced, nor is a source coming back after a failure.

notifications = true

Sounds

Something new to do also rings, once per refresh, with the sound of the most pressing new task.

[sounds]
enabled = true
new_task = "Glass"

[sounds.rules]
review_requested = "Ping"
draft_to_finish = "none"
KeyValue
new_taskA system sound by name, or a file: "~/sounds/ding.wav". The default is Glass on macOS and message-new-instant elsewhere.
[sounds.rules]A sound of its own for a rule. "none" keeps it quiet.
aki sounds
aki sounds Glass

The first lists the sounds that can be named; the second plays one.
